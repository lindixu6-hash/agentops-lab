# AgentOps Lab 一页 PRD

> 版本：v0.1  
> 日期：2026-08-17  
> Owner：lindixu6-hash  
> 状态：首轮用户验证

## 1. 一句话定义

AgentOps Lab 是一个隐私优先的本地 AI Agent 评测与运营工作台：用户导入 CSV 或 JSON 运行日志，即可获得任务成功率、失败类型、版本对比、成本与延迟分析，以及可下载的迭代复盘报告。

## 2. 目标用户与问题

**核心用户**

- 正在交付 Agent MVP 的 AI 产品经理；
- 需要定位失败案例、管理 Prompt 版本的 AI 运营人员；
- 没有完整可观测性平台的独立开发者和小团队。

**高频问题**

- 日志散落在表格和控制台，复盘依赖人工筛选；
- 只看平均准确率，无法定位失败类型及高风险样本；
- Prompt / Agent 版本迭代后缺少同口径对比；
- 成功率、人工接管、成本和延迟没有放在同一个决策视图；
- 业务日志敏感，不适合上传第三方 SaaS。

## 3. 产品目标

在不上传原始数据的前提下，让用户在 3 分钟内完成一次“导入日志 → 发现问题 → 下载复盘报告”的完整任务。

**北极星指标**

完成一次有效分析并下载报告的用户比例。

**首轮验证指标**

| 指标 | 目标 |
| --- | ---: |
| 任务完成率 | >= 80% |
| 首次分析中位耗时 | <= 3 分钟 |
| 报告有用度（1-5 分） | >= 4.0 |
| 失败分类人工复核准确率 | >= 85% |
| 用户愿意再次使用 | >= 60% |

## 4. MVP 范围

**必须有**

1. 导入 UTF-8 CSV 或 JSON 数组；
2. 自动识别常见字段别名并校验数据；
3. 计算成功率、P95 延迟、成本、人工接管率与用户评分；
4. 展示失败类型分布和 Prompt / Agent 版本对比；
5. 根据指标生成带优先级的迭代建议；
6. 下载 Markdown 和 JSON 报告；
7. 示例数据一键体验；
8. 全程浏览器本地处理，默认不上传日志。

**比赛增强**

1. 封装为 `local-agentops` Skill；
2. 使用本地 OpenVINO GenAI 模型归纳失败原因与行动建议；
3. 支持确定性规则模式，模型不可用时不调用云服务；
4. 在 TRAE Work / WorkBuddy 类 Host 中验证稳定调用；
5. 发布代码、测试、技术文章和完整运行证据。

**本期不做**

- 连接生产数据库或第三方观测平台；
- 自动修改 Prompt 或直接发布线上版本；
- 团队权限、云端账号和长期数据存储；
- 用浏览量冒充有效用户或伪造用户反馈。

## 5. 核心流程

1. 用户选择示例数据或导入文件；
2. 系统展示字段识别结果与无效行数量；
3. 系统生成总体指标、失败类型和版本对比；
4. 用户查看优先建议及其计算依据；
5. 用户下载报告并提交匿名反馈；
6. 产品团队依据任务完成率、耗时和反馈迭代。

## 6. 数据协议

最小字段：

| 字段 | 类型 | 必填 | 示例 |
| --- | --- | --- | --- |
| `task_id` | string | 是 | `task-001` |
| `success` | boolean | 是 | `true` |
| `latency_ms` | number | 否 | `1820` |
| `cost_usd` | number | 否 | `0.013` |
| `human_review` | boolean | 否 | `false` |
| `error_type` | string | 否 | `tool_error` |
| `prompt_version` | string | 否 | `v2` |
| `user_rating` | number | 否 | `4` |

隐私要求：

- 示例数据必须为合成数据；
- 原始输入、输出文本默认不进入报告；
- 公共仓库、文章和截图不得出现 API Key、邮箱、手机号、客户名或内部业务数据；
- 用户研究只记录匿名编号和明确授权的引语。

## 7. 决策规则

- 成功率低于 80%：P0，优先分析最高频失败类型；
- 人工接管率高于 25%：P1，检查工具权限、异常恢复和交互确认；
- P95 延迟高于 8 秒：P1，检查串行工具调用和模型路由；
- 失败任务平均成本高于成功任务：P1，增加早停与调用预算；
- 新版本成功率下降超过 5 个百分点：P0，建议回滚并复现回归样本；
- 有效记录少于 20 条：提示样本不足，不输出强结论。

## 8. 验收标准

- 示例 CSV 和 JSON 均可生成一致的核心指标；
- 对错误文件给出明确、可恢复的提示；
- 1000 条记录在普通笔记本上 1 秒内完成确定性分析；
- 报告包含数据口径、样本数、时间戳、指标、失败分布、版本对比和建议；
- 核心逻辑具备自动化测试；
- 桌面和移动端无内容重叠，长错误类型可正常换行；
- 不联网也能完成基础分析和报告下载。

## 9. 14 天验证节奏

- D1-D2：MVP、示例数据、自动化测试；
- D3-D4：5 位用户首测，记录任务完成率和耗时；
- D5-D7：修复前三大问题，加入本地模型 Skill；
- D8-D10：第二轮测试、评测报告和演示视频；
- D11-D12：ModelScope Skill 与技术文章；
- D13-D14：比赛提交、开源发布、内容传播和数据复盘。
