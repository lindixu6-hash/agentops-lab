# AgentOps Lab 首轮 5 位用户测试

> 研究目标：验证目标用户能否独立导入日志、识别最重要问题并下载可执行的复盘报告。  
> 禁止：代填反馈、诱导好评、把模拟数据写成真实用户数据。

## 招募标准

- 2 位 AI Agent / LLM 应用开发者；
- 2 位 AI 产品或 AI 运营从业者 / 实习生；
- 1 位独立开发者或 AI 工具重度用户；
- 最近 3 个月内至少调试或评估过一个 AI 工作流。

## 测试任务

向参与者提供产品链接和示例数据，只读以下任务，不进行操作提示：

> 你需要判断一个 Agent 版本是否适合继续放量。请导入日志，找出最需要优先处理的问题，比较不同版本表现，并下载一份复盘报告。

成功条件：

1. 成功导入文件；
2. 正确指出成功率最低或回归明显的版本；
3. 找到最高频失败类型；
4. 下载 Markdown 或 JSON 报告。

## 开场同意口径

> 本次测试约 10 分钟，用于改进 AgentOps Lab。我们只记录匿名编号、任务完成情况、耗时和你主动提供的反馈，不收集账号密码、业务日志或其他敏感信息。你的原始文件只在浏览器本地处理。你可以随时停止测试。是否同意参与并允许我们匿名引用你的反馈？

只有明确回答“同意”后才能开始记录。

## 结束问题

1. 你认为这批日志最需要先处理什么？为什么？
2. 哪个指标或建议最有用？
3. 哪一步最难理解或最耗时？
4. 你目前用什么方式完成同类工作？
5. 什么条件下你会再次使用或推荐它？
6. 你是否同意匿名引用刚才的某句话？请确认准确表述。

## 数据录入

完成后把匿名结果填入 `research/first-5-users.csv`。空白记录不计入真实用户数。

计算口径：

- 任务完成率 = 完成全部四项成功条件人数 / 有效参与人数；
- 中位耗时 = 有效参与者完成或放弃任务的用时中位数；
- 判断正确率 = 正确识别主要回归或最高频失败的人数 / 有效参与人数；
- 平均有用度 = 有效评分总和 / 有效评分人数；
- 再使用意愿 = 回答“是”的人数 / 有效参与人数。

## 招募文案

### 私聊版

我在测试一个完全本地处理数据的 Agent 评测工具。它可以导入 CSV / JSON 日志，自动生成成功率、失败类型、版本对比、成本和延迟复盘。想找 5 位最近做过 AI Agent / LLM 产品的人完成一次 10 分钟可用性测试，不需要提供真实业务数据，使用合成样例即可。测试只记录匿名任务结果，完成后我会把最终评测模板和报告发给你。

### 社群版

招募 5 位 Agent 开发者 / AI 产品运营做 10 分钟产品首测：

- 不上传业务数据，浏览器本地分析；
- 提供合成示例，不需要准备材料；
- 任务是判断一个 Agent 版本能否继续放量；
- 测试后可获得开源评测模板和个人复盘报告。

愿意参与请回复“AgentOps 首测”，我会发送测试链接和匿名编号。
